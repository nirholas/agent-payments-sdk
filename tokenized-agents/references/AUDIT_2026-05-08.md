## Resolution of previously unverified claims

### Claim A: `agent_buyback_trigger` / `token_agent_payment_in_currency` semantics

Resolved by cross-referencing the full account list of `agent_buyback_trigger`
against `agent_distribute_payments` in both IDLs plus the TS builder in
`src/solana/PumpAgentOffline.ts`.

Key findings:
- `agent_buyback_trigger` does NOT include `buyback_vault` in its account list.
  It includes `burn_currency_mint_vault` instead.
- `burn_authority` (account #7) has PDA seeds `["buyback-authority", mint]` —
  identical seeds to `buyback_authority` in `agent_distribute_payments`. They
  are the same on-chain account, renamed to avoid confusion with the
  `global_buyback_authority` signer.
- `burn_currency_mint_vault` is an ATA of `currency_mint` owned by
  `burn_authority`, derived using the runtime `token_program_currency` account.
  For SPL Token currencies (USDC, wSOL), this resolves to the same address as
  `buyback_vault` from `agent_distribute_payments` (which uses the hardcoded
  SPL Token program bytes as the ATA seed).
- `token_agent_payment_in_currency` is writable. Based on the account
  structure, it is updated for accounting purposes during the buyback (e.g.
  recording the amount processed or zeroing a counter). The actual currency
  tokens used in the swap come from `burn_currency_mint_vault`.
- SKILL.md now reads: "inferred from IDL constraints — not confirmed against
  on-chain Rust" rather than "unverified — requires source review".

### Claim B: Live mainnet state of `Global.whitelisted_quote_mints`

Resolved by removing the stale `docs/mainnet-verification-report.md`
reference. SCENARIOS.md Scenario 3 now provides inline TypeScript for
fetching the live whitelist at runtime via `program.account.global.fetch()`
and `program.account.globalConfig.fetch()`. No static snapshot is maintained
here because these are admin-mutable runtime values.
